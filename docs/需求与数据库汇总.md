# 华中农业大学 · 校园运动场馆预约系统
## 需求 · 功能边界 · 数据库汇总

> 本文按「为什么做 → 做什么 → 边界在哪 → 怎么设计 → 数据库怎么落」的顺序整理，
> 内容与当前原型（`index.html` + `js/*.js`）的实际行为一致。

---

## 一、为什么做

### 1.1 现状

学校现有的体育场馆预约系统解决了「订场地」，但有三块空白：

1. **没有排球场的预约入口。** 能约的只有羽毛球、乒乓球、网球等，排球场（老场、新场、室内场）只能线下占场、托人问。
2. **没有组队能力。** 想打球只能在微信群里喊人，凑齐与否全凭运气。
3. **没有用户之间的交互。** 没有个人主页、没有交流区、没有好友，打完就散。

### 1.2 由此产生的痛点

| 痛点 | 具体表现 | 本项目的做法 |
| --- | --- | --- |
| 排球场约不到 | 只能线下占场，信息不透明，去了可能被占 | 排球场（老场 8 / 新场 6 / 室内 1）全部纳入线上预约，与羽球乒乓共用同一套流程 |
| 人数凑不齐 | 群里喊人靠刷屏，容易凑不齐、重复约 | 组队模块：发布招募 → 申请入队 → 队长审核 → 满员才能提交场地预约 |
| 没有约束 | 谁都能报、谁都能鸽、一人占多个馆 | 实名学号注册；同一时段跨场馆互斥；队长可管理成员；管理员审核预约 |
| 场地信息不透明 | 不知道哪个时段空着 | 日历式时段表：绿=可约、灰=已约、蓝=我的预约、黄=待审核 |
| 缺少交流 | 没有圈子，找不到固定球友 | 交流中心（发帖 / 评论 / 点赞 / 收藏 / 举报）+ 好友体系 |
| 垃圾信息无人管 | 举报无门 | 举报 → 管理员处理（驳回 / 警告 / 删除帖子 / 禁止发帖 / 封禁账号 / 解除限制） |
| 管理员通知触达 | 临时闭馆、赛事征用没人知道 | 管理员发布通知，置顶在交流中心顶部（最多 3 条），更早的进「历史通知」 |

### 1.3 一句话定位

**在「场馆预约」之上补齐排球场，并加上「组队找搭子」和「用户间交互」，让想运动的人和空着的场地能对上。**

## 二、做什么 · 不做什么（功能边界）

### 2.1 本项目做

- 全量场馆线上预约（9 类 / 80 片场地，本月内、08:00–22:00 分时段）
- 预约申请与管理员审核闭环
- 组队（发招募 / 申请入队 / 邀请好友 / 成员管理 / 组队提交预约）
- 交流中心（帖子、评论、点赞、收藏、举报、管理员通知）
- 好友（申请—同意、删除、拉黑）
- 站内红点提醒
- 管理后台（审核、通知、举报处理、统计）
- 中英文切换

### 2.2 本项目**不做**（当期边界）

| 不做的事 | 原因 |
| --- | --- |
| 在线支付 / 收费 / 押金 | 校园场馆免费，本期无收费场景 |
| 门禁闸机、灯光、场地传感器对接 | 无硬件接口，不在原型范围 |
| 学校统一身份认证（CAS / 教务处账号） | 先用「学号 + 密码」自建账号，后续可换 |
| 短信 / 微信 / 邮件推送 | 提醒走站内红点，不做外部通道 |
| 原生 iOS / Android App | 只做 Web，响应式适配手机浏览器 |
| 多校区 / 跨学校 | 只服务本校一个校区 |
| 管理员代客预约 | 管理员只审核，不代替用户下单 |
| 信用分 / 违约扣分 | 只保留「取消预约」入口，不做惩罚机制 |

### 2.3 关键业务边界（规则与数值）

| 规则 | 边界值 | 说明 |
| --- | --- | --- |
| 可预约日期 | 本月 1 日 ~ 本月最后一天 | 不能订下月，也不能订昨天 |
| 开放时间 | 08:00 – 22:00 | 每小时一段，共 14 段（08:00-09:00 … 21:00-22:00） |
| 场地规模 | 9 类 / 80 片 | 见 4.2 明细 |
| 同一场地同一时段 | 仅 1 条生效预约 | 已「拒绝」的不占位，可被重新预约 |
| 同一用户同一时段 | 跨场馆仅 1 条 | 预约与组队都受此约束，冲突时提示先取消原预约 |
| 预约理由 | **必填** | 展示给管理员审核 |
| 预约人数 | **不做要求和限制** | 名单选填，人数多少都能提交 |
| 组队需要人数 | 2 ~ 15，且 ≥ 当前已加入人数 | 队长可事后修改 |
| 「过期」判定 | 日期早于今天，或今天且时段 ≤ 当前小时 | 过期的预约置灰、不可取消；过期的队伍只读 |
| 过期预约保留 | 7 天 | 超期自动清理，个人主页与后台都不再显示 |
| 过期组队清理 | 过当天 24 点 | 从组队列表移出并归档，历史仍可在「我的组队」查看 |
| 通知置顶条数 | 最多 3 条 | 更早的自动进「历史通知」 |
| 举报去重 | 同一人对同一对象只能举报 1 次 | 防刷 |
| 封号效果 | 禁止发帖 / 评论 / 加好友，**仍可预约** | 保留基本运动权利 |
| 队伍已提交预约后 | 不可退出 / 移人 / 改配置 / 解散 | 需队长先取消预约，避免名单不一致 |

## 三、角色与权限

| 角色 | 登录方式 | 能做什么 |
| --- | --- | --- |
| 学生用户 | 学号 + 密码 | 预约、取消、组队、发帖评论、加好友、查看自己主页 |
| 管理员 | 管理员号 + 密码 | 预约审核、发布/删除通知、处理举报（驳回 / 警告 / 删除帖子 / 禁止发帖 / 封禁账号 / 解除限制）、查看统计 |

- 学生与管理员**登录入口分开**，登录后进入完全不同的界面（`#/book…` vs `#/admin`）。
- 超级管理员由**初始化脚本自动创建**（默认账号 `admin`），首次登录**强制修改密码**。

## 四、功能设计

### 4.1 账号与登录

- **注册**：姓名 + 学号（6–20 位数字）+ 密码（≥ 6 位），学号唯一。
- **学生登录**：学号 + 密码。
- **管理员登录**：管理员号 + 密码；`mustChangePassword` 为真时弹窗强制改密。
- **个人资料**：姓名、年龄、年级、专业、班级、爱好、个人介绍、头像（可上传）、性别。

### 4.2 场馆与时段

| 场馆 | 片数 | 位置 |
| --- | --- | --- |
| 羽毛球馆 | 20 | 东体育馆 3 楼 |
| 排球老场 | 8 | 第二运动场 |
| 排球新场 | 6 | 第三运动场 |
| 排球室内场 | 1 | 西体育馆 |
| 乒乓球馆 | 36 | 东体育馆 1 楼 |
| 室内网球馆 | 3 | 东体育馆 2 楼 |
| 室外网球场 | 4 | 室外场地 |
| 游泳馆（男） | 1 | 东体育馆 游泳馆 |
| 游泳馆（女） | 1 | 东体育馆 游泳馆 |

每一片场地有：**编号**（羽01…羽20 / 排01 / 乒01…）、**所属类型**、**位置**、**图标**、以及按日期 × 时段的**预约状态**。

> 注：游泳馆目前仍在配置中，如需下线只需停用这两条类型配置即可，不影响其他场馆。

### 4.3 预约流程

1. 选场地类型 → 看时段表（绿=可约 / 灰=已约 / 蓝=我的 / 黄=待审核 / 灰底=已过期 / 红=时段冲突）
2. 点绿色格子 → 填**预约理由**（必填）+ 同行名单（选填）
3. 提交 → 状态 `待审核` → 管理员同意后为 `已通过`，拒绝为 `已拒绝`
4. 用户可随时取消未过期的预约；被拒绝的预约保留记录、不置灰、无取消按钮

### 4.4 组队

- **创建队伍**：比赛/活动标题、场馆、日期、时段、需要人数（2–15）、联系方式、备注。
- **加入队伍**：陌生人 → 提交申请，**队长同意后**才进队；也支持**队长邀请好友**，好友可同意/拒绝。
- **队伍管理（仅队长）**：同意/拒绝入队申请、修改需要人数、移出已入队成员（二次确认）、解散队伍。
- **成员**：可随时退出（未通过的申请可直接撤销）；队伍已提交预约后不能退出。
- **队伍动态**：申请、撤销、退出、被移出、加入、解散都会记录并在「管理队伍」里显示。
- **提交预约**：人数满员后队长提交；若该时段该场地已被占，则给出**同时间段其他空闲场地**供重选；若该时段无任何空场，则引导「更换时间段」。
- **过期队伍**：过当天 24 点自动从组队列表移除并入档。

### 4.5 交流中心与通知

- 发帖、评论、点赞、收藏、举报。
- 管理员通知置顶在顶部（最多 3 条），旁边的「历史通知」查看更早的通知。
- 通知由管理员用中文发布；英文模式下自动翻译显示。
- 帖子列表按时间倒序；被举报且成立的帖子可被管理员删除。

### 4.6 好友与互动

- 在交流中心点头像、在组队里点成员姓名 → 进入对方主页并可加好友。
- 加好友需对方同意；同意后被加的一方收到红点。
- 已是好友：可**删除好友**（二次确认）、**拉黑**（二次确认，拉黑后从好友列表消失）。
- 非好友也可以直接拉黑；被拉黑的人**不能再加对方好友**，提示「您已被对方拉黑」。

### 4.7 红点提醒体系

两层层级：**顶部导航红点** + **个人主页内标签红点**。

| 触发事件 | 红点位置 | 消除方式 |
| --- | --- | --- |
| 预约被同意 / 拒绝 | 「个人主页」导航 + 「我的预约」标签 | 打开个人主页即消除 |
| 帖子被评论 / 点赞 / 收藏 | 「我的帖子」标签 | 点进「我的帖子」 |
| 收到好友申请 / 申请被同意 | 「我的好友」标签 | 点进「我的好友」 |
| 队伍状态变化（入队被同意、被移出、队伍解散…） | 「我的组队」标签 | 点进「我的组队」 |
| 收到组队邀请 / 好友回应邀请 | 「申请组队」标签 | 点进「申请组队」 |
| 有人申请入队 / 撤销申请 / 退出队伍 | 导航「组队」+ 该队伍的「管理队伍」按钮 | 进入组队页 / 打开该队伍的「管理队伍」 |

### 4.8 管理后台

- **预约审核**：待处理列表按活动时间排序（越接近当前越靠前）；过期的置灰且不可操作；超 7 天自动清除。
- **通知管理**：发布、删除通知。
- **举报处理**：查看举报 → 驳回举报 / 警告用户 / 删除帖子 / 禁止发帖 / 封禁账号 / 解除限制。
- **统计概览**：用户数、预约数、待审核数、帖子数、队伍数、待处理举报数、各场馆预约分布。

### 4.9 国际化

- 全站中英文切换（`中文 / EN`），语言偏好本地保存。
- 管理员用中文发布的通知，在英文模式自动翻译。

### 5.4 最关键的两条约束（防超卖 / 防冲突）

`bookings` 用「生成列 + 唯一索引」保证同一时段只有一条**生效**预约：

```sql
active_flag TINYINT UNSIGNED GENERATED ALWAYS AS
  (IF(status IN ('pending','approved'), 1, NULL)) STORED,

UNIQUE KEY uk_slot      (venue_id, book_date, slot_start, active_flag),
UNIQUE KEY uk_user_slot (user_id,  book_date, slot_start, active_flag)
```

- `uk_slot`：**同一片场地、同一时段**只能有一条生效预约 → 解决场地撞车。
- `uk_user_slot`：**同一个人、同一时段**跨场馆只能有一条 → 解决「一人同时占多个馆」。
- `active_flag` 为 `NULL` 时不参与唯一性 → 取消/拒绝后可以重新预约。

数据库抛出重复键（1062）时，接口层转成友好提示并返回同时间段的可选场地。
